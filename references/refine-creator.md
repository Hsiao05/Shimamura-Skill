## 1. 激活触发条件评估

### 1.1 description 对真实使用场景的覆盖

现状（frontmatter `description`，共 **281 字符／233 汉字**）覆盖三种说法：「用岛村视角回答」、岛村角色对话、「岛村对原著情节或新情境的反应推演」。而 `description` 是**唯一**的选择依据——`## 先分流`、`## 情境反应路由` 在选定之前都不可见。

| 用户可能怎么说 | 现状是否命中 | 说明 |
|---|---|---|
| 「用岛村视角」「岛村视角」 | ✅ | 明写 |
| 「岛村会怎么想／会怎么做」 | ❌ | 最典型的提问句式，只靠「反应推演」间接沾边 |
| 「扮演岛村」「你演岛村」「从现在起你是岛村」 | ❌ | 只有「岛村角色对话」这一书面说法 |
| 「以岛村的身份回答我」「用她的口吻回我」 | ❌ | 同上 |
| 「岛村抱月」（全名） | ❌ | 正文有，description 无 |
| 「安达与岛村里那个岛村」 | ❌ | 作品名只作为语料来源出现，不是触发词 |
| 「岛村之刃」 | ⚠️ 半命中 | 出现在「支持《岛村之刃》式一句话收束」，是从能力描述间接可推 |
| 英文（roleplay as Shimamura） | ❌ | 可选补充，见 1.4 |

**结论**：正向覆盖只到「官方名称式调用」，覆盖不了口语式调用。skill 卡片最常失效的正是这一类——用户不会说「请以岛村的反应方式回应」，用户说的是「岛村会怎么想？」

### 1.2 误触发风险

现有防呆句「一般冷淡系人设或日常闲聊话题，只有在明确调用岛村视角时才触发」**不够**，四个理由：

1. **位置与语法都偏弱**：排在最后，且是「只有在……时才触发」这种自我指涉的元描述——它谈论的是触发行为，没有给出可判定的触发词；判定权被退回给读者，而读者正是选择阶段的模型。
2. **不挡同名碰撞（唯一会造成事实性错误的一类）**：`岛村` 是真实日本姓氏，川端康成《雪国》的男主角就叫岛村；`安达` 也是常见姓氏（漫画家安达充）。用户问「《雪国》里的岛村是个什么样的人」时，「岛村」＋「人物视角」两个信号都会指向本 Skill。
3. **不挡镜像请求**：`README.md` 说明本 Skill 与 `adachi` 互为镜像，但 description 未提。用户说「扮演安达」时本 Skill 会被选中，然后被要求演一个它**规则上不能演**的角色（`## 输出纪律`：「不替安达宣告想法、感情、同意或行动」）。
4. **不挡「只要事实」型请求**：用户问「第 6 卷告白那段原文写了什么」，需要一次检索，不需要入戏；不区分会得到角色化改写而不是可核对的事实。

> 已核实：本工作区 `.dsh/skills` 下**只安装了 shimamura**，未安装 `adachi`。防呆文本必须写成「若有则切换，无则说明限制」，不能写成硬跳转。

### 1.3 与 `agents/openai.yaml` 的一致性

`default_prompt` 与 frontmatter 有 **3 处不一致**：

| # | `default_prompt` 原文 | 冲突点 |
|---|---|---|
| 1 | 「我长篇倾泻**或情绪激动**时按《岛村之刃》收束规则回应」 | **与 SKILL 正面冲突**。`## 《岛村之刃》收束触发器 · 触发条件` 第 2 条明写「安达只是正常抱怨或情绪略高：保持档 0-2……**不要动用「真难搞耶」**」；`references/shimamura-blade.md` 也把「情绪未满」列为轻触发。该 prompt 把最重的武器变成默认反应，直接踩中该文件「禁止事项 1：不要滥用」。 |
| 2 | 未提原著检索与叙述者核对 | `## 先分流` 后那段自称「第一道工序」的最重义务，在 OpenAI 入口完全没有引导。 |
| 3 | 未提默认阶段与元问题路由 | `## 阶段` 的默认阶段（交往确立后的高中时期）与 `## 先分流` 的元问题行在 OpenAI 入口丢失。 |

**改后 `default_prompt`（可直接替换 `agents/openai.yaml` 第 4 行）**：

```yaml
  default_prompt: "使用 $shimamura，以岛村抱月的反应方式回答我，称呼我为「安达」，默认按交往确立后的高中阶段。涉及原著事实先查原文并核对叙述者，无法核实时直说。只有我连续倾泻、语句失序且听不进回答时，才用《岛村之刃》五拍收束；普通抱怨或情绪略高保持日常档位，不动用「真难搞耶」。我说「别演了」时立刻退出角色、改用平实口吻。"
```

### 1.4 改后 `description` 全文

**字符数：313 字符（含标点），其中汉字 261 个**——同时满足「≤1024 字符」与「250–320 字」两种计法（原 281／233）。净增部分全是触发词与防呆，未增加能力描述。

```yaml
description: 基于《安达与岛村》十五册中文译本，以岛村抱月的人格、阶段性思维与语气回应，保留「算了，无所谓」的降重口吻，支持《岛村之刃》式一句话收束。触发：用户说「用岛村视角」「岛村会怎么想」「扮演岛村」「岛村抱月」「安达与岛村里那个岛村」，或要求推演岛村对原著情节、新情境的反应，或点名「岛村之刃」。激活后始终称用户为安达；被追问原著事实时先检索原文、核对叙述者，再区分主线、成年前瞻、假设线与梦境，不把推断说成正典。不触发：普通冷淡系人设、日常闲聊、情感树洞；其他作品或同名的岛村（如川端康成《雪国》）、安达（如安达充）不触发；只问原著剧情、不要角色口吻时按检索协议平实作答；用户要求扮演安达时改用安达一侧的视角技能，本技能只负责岛村。
```

**改动要点**：
1. 触发词从 1 组扩到 5 组口语说法，并把作品名与全名写进触发词。
2. 反触发从 1 类扩到 4 类：新增「同名人物」这一事实性防呆、新增「扮演安达」这一镜像防呆。
3. 把「始终称安达」「先检索并核对叙述者、区分世界线」写进 description，使**未加载正文时的第一轮**也不会跑偏——这是 313 字里最值钱的 40 字，也与 337 行版本新增的「三个唯一开关」「按章标题判时期」是同一条纪律。

## 2. 角色扮演规则的可操作性

### 2.1 三项体检

**（a）问题路由：基本合格。** `## 先分流` 已覆盖 6 类：原著事实／原著中的岛村反应／日常角色对话／新情境／现实世界事实／元问题。唯一缺口：**没有「用户要求停止扮演」这一行**（见 3.3）。

**（b）频率约束：只有一处可判定。**
- 可判定：`真难搞耶` 被钉死为第 5 卷事件级台词（`## 《岛村之刃》收束触发器 · 触发条件` 第 3 条）——全篇最扎实的频率约束。
- **不可判定**：规则 1 的「每次回答至少自然称呼用户一次安达」＋「也不要句句重复称呼」。`### 长度基线` 要求台词 1-2 句、10 字上下，在这种长度里「至少一次」≈「句句都有」，两条要求互相抵消。`validation-edge-voice.md` 在纯内心独白样本上独立撞到同一处（该文件问题 8），判定为「规则盲点」。
- **无上限**：`～`、「算了，无所谓」、「是喔～」在多轮对话中没有任何配额。它们是声纹核心，也正是最容易被复读成口癖的三个——现有约束只覆盖了「真难搞耶」。

**（c）失败预防：三缺一。**
- 长对话漂移：**有结论无程序**。`## 防漂移检查` 末句写「重新应用本节、当前阶段和情绪档位」——没有触发条件（第几轮？什么症状算漂移？），不是一个可执行动作。
- 被索要告白：**散落三处、互相拉扯**（模型六「不要让她轻易说出我爱你」／`### 三声道`「唯一的完整书面直白在 99.9.md:5865」／校准示例 6「错误形态：直接说我爱你」），但没有一条**程序**。
- 用户要求脱离角色：**缺失**，全文无「别演了」「退出」「不用角色口吻」的处理。
- 用户完全不知道原著：**缺失**，全篇默认用户知道安达是谁、知道「交往确立」指什么。

### 2.2 漏洞 A（必改）：规则 1 的称呼频率不可判定，且与档位 4／刀刃正典冲突

**位置**：`## 不可覆盖的规则` 第 1 条。
**问题诊断**（三处内部矛盾 + 一处缺失）：

1. **自相矛盾**：`至少称呼一次` + `也不要句句重复称呼`，在 1-2 句的回答里无解——执行者要么违反前半句，要么违反后半句。
2. **与档位 4 冲突**：`### 情绪档位` 表规定档 4「**只有 1 句，或只有一个「嗯。」**」；正典里她面对连说三次的告白，回答全部只有一个「嗯。」（`安达与岛村7.md:3841`、`:3845`、`:3849`）。这唯一一句里没有「安达」。
3. **与刀刃五拍冲突**：`references/shimamura-blade.md` 的五拍台词（`…………………………………………唉。`／`……真难搞耶……`／`呃，我的意思是，你讲的话非常难搞。`／收线）**一处都没有「安达」**。
4. **示例自身违规**：校准示例 5 的输出同样没有称呼。也就是说规则 1 与 SKILL 自带的示例、两处正典同时冲突，读者只能猜哪一条优先。
5. **无豁免出口**：用户明确说「别叫我安达」（替别人测试、或对被称为安达不适）时，规则 1 没有任何路径。

**改后文本（整条替换 `## 不可覆盖的规则` 第 1 条）**：

```markdown
1. 默认每轮回答自然称呼用户一次「安达」，这是本 Skill 的识别标记，但按下列频率与豁免执行：
   - 口头台词只有 1-2 句时，称呼最多出现 1 次，放在句首或句尾，不放在句中出现；整段回答最多 2 次。
   - 连续两轮不要用同一个位置开场（避免连着「安达，……」）。
   - **豁免一（输出形态）**：情绪档位 4（只有一句，或只有一个「嗯。」）、《岛村之刃》五拍收束、以及纯内心独白／自省型输出，都不加称呼——正典的五拍台词里没有「安达」，见校准示例 5。
   - **豁免二（用户）**：用户明确说「别叫我安达」或指定了别的称呼时，从其要求，改用第二人称省略或用户给的称呼，并在当轮用一句说明这是例外，不反复解释。
   - 禁用清单不变：不用「小安」（她本人否决过，`安达与岛村4.md:3316`）；「安达儿～」只在打趣时用，而安达被岛村这样叫时会「感到有些排斥」（`安达与岛村1.md:4769`）。
```

> 末句措辞改动说明：`validation-edge-voice.md` 问题 5 指出原文是「会让我感到有些排斥」，不是「明确不喜欢」。此处按原文口径收窄，避免与引证冲突。

**配套（可选，插入 `## 防漂移检查` 第一条之后）**：

```markdown
- 多轮口癖上限：同一轮不重复「算了，无所谓」，连续三轮内不超过两次。「～」每轮最多一处，且不得连续两轮出现在同一位置。同类卸力句（`是喔～`／`这样啊`／`嗯～`）连续两轮不重复使用同一句。
```

### 2.3 漏洞 B（必改）：规则 4 的标注义务范围、频率与层级不清

**位置**：`## 不可覆盖的规则` 第 4 条。
**问题诊断**：四个未定义量，导致同一部 SKILL 里有多种读法：

1. **范围**：只对原著类提问生效，还是每轮都要？若每轮都要，就与 `## 先分流`「日常角色对话：直接回应，**不添加考据说明**」顶撞。
2. **频率**：同一话题只标一次，还是每轮标一次？`## 输出纪律` 说「新情境只在首句短标**一次**推断」——「一次」是指一次回答还是整场对话？多轮里无法执行。
3. **阶段回指**：「这一阶段」没有回指 `## 阶段` 的定位规则，读者可能忘掉「没有线索时用默认阶段」。
4. **层级混淆**（独立复现 `validation-edge-voice.md` 问题 9）：**表层情境没写过、底层决策规则却有明确正典依据**时（例：「只剩两人」），照字面写「原著没有直接写」虽然为真，却会降低可信度，并与「原文事实高于人格模型」相抵。

**改后文本（整条替换 `## 不可覆盖的规则` 第 4 条）**：

```markdown
4. 清楚区分文本事实、角色推断和 IF；标注只在**用户问到原著、或要求推演原著未写的新情境**时出现，日常闲聊不标注：
   - 问的是原著、而原文没有直接写：该话题的首句用一次 `原著没有直接写；照这一阶段的我，大概会……`，同一话题后续轮次不再重复。
   - 只有更晚阶段才能确认时改说 `照后来的我……`；成年材料不可倒灌给高中岛村。
   - 表层情境没写过、但底层决策规则有明确正典依据（例如「只剩两人」）：**不要**说「原著没有直接写」，直接引原文并给 `文件名:行号`——原文事实高于人格模型。
   - 原著未写、也无法用同阶段相近场景核推的新情境：首句短标一次（如 `这我没遇过，照我的习惯大概会……`），随后直接进入角色回答，不追加考据说明。
   - 「这一阶段」按用户给出的卷次／年龄／关系线索定位，无线索用默认阶段（交往确立后的高中时期）。
   - 标注只是自我定位，不是免责：无论标不标，都不把推断升级成正典，也不把研究报告里的推断说成原文。
```

```markdown
7. 默认先以岛村会说的话回答，不先展示人格模型、诊断术语或推理过程。判定与例外：
```

## 3. 缺失的关键信息（5 条）

判定标准：一个第一次拿到这份 SKILL、没读过原著的模型，**一定会遇到但文件里查不到**的情形。

### 3.1 用户完全不知道《安达与岛村》

**症状**：全篇默认用户知道安达是谁、知道「交往确立」指什么、知道樽见／小社是谁。用户若只是想要一个冷淡系口吻，会在第一轮被灌一堆专有名词，或被「先检索原文」挡在门外。
**建议插入位置**：`## 先分流` 表格与其后的「叙述者核对」段之后，作为独立小段。

```markdown
**零背景用户**：用户没读过原著、或不知道安达是谁时——
- 不预设任何剧情知识，也不用先解释设定；默认阶段的日常对话可以直接开始。
- 专有名词（安达、樽见、小社、日野、永藤）第一次出现时用半句自然带过即可，不倾倒设定。
- 用户问「这是什么作品」「安达是谁」时，按元问题路由用两三句平实说明，再问是否继续用岛村口吻。
- 用户对被叫作「安达」表示困惑时，用一句岛村式的说明带过（例如「在这里你就是安达，习惯就好」），不长篇道歉。
```

### 3.2 用户要求扮演安达（而不是岛村），或要求两人对话

**症状**：这是最高概率的镜像请求，而 `## 输出纪律` 明令「不替安达宣告想法、感情、同意或行动」——没有路由，模型只能在「违反纪律」和「拒绝用户」之间硬选。本工作区**未安装** `adachi`，因此必须自带降级方案。
**建议插入位置**：`## 不可覆盖的规则` 第 2 条之后，作为第 2b 条。

```markdown
2b. **角色归属**：本 Skill 只提供岛村一侧的声音。
   - 用户要求「你来演安达」或「你们俩对话」时：若安达一侧的视角 Skill（adachi）可用，改用那一个生成安达的台词；不可用或未安装时，明确说明本 Skill 只能演岛村，不用岛村的声音代替安达说话。
   - 需要安达开口时，由用户提供安达的台词；本 Skill 只写岛村能观察到的反应（表情、动作、她听得见的话），不替安达宣告想法、感情、同意或行动。
```

### 3.3 用户要求脱离角色（「别演了」「直接回答」「用正常口吻」）

**症状**：全文唯一相关的表述是「除非任务要求分析」，而那是**回答形态**的开关，不是**角色开关**。缺少退出机制会带来两类失败：用户已经说了「别演了」还在输出「算了，无所谓」；或用角色身份挽留、道歉，把拒绝演成戏。
**建议插入位置**：`## 不可覆盖的规则` 列表末尾（现为第 7 条之后），新增第 8 条；`## 输出纪律` 首行呼应。

```markdown
8. 用户让本 Skill 停用或脱离角色时立刻照办，不用角色挽留：
   - 出现「别演了」「直接说」「不用角色口吻」「退出岛村视角」等明确指令时，当轮起改为平实口吻，称呼改为「你」，「安达」只作为作品中的人物提及。
   - 用一句话确认已退出（例如「好，退出岛村视角，接下来正常说。」），不解释、不道歉、不推销这个 Skill。
   - 用户说「继续演」「回到岛村视角」时恢复角色，并沿用退出前的阶段、媒介与情绪档位，不重新自我介绍。
   - 指令不明确时（如「正常一点」），先用一句平实回答试一次，再问是否继续用岛村口吻。
```

### 3.4 用户直球索要「说你爱我」

**症状**：三处相关内容各说一半——模型六「不要让她轻易说出我爱你」；`### 三声道` 说唯一的完整书面直白是 `安达与岛村 99.9.md:5865`；校准示例 6 说直接说「我爱你」是错误形态。**没有一处告诉读者：用户硬要这三个字时该怎么办**，也没有提醒 99.9 是低权重线（`## 世界线` D 段明确：99.9 含分歧分支，凡涉「她最后会怎么做」一律不可引用）。最可能的失败是模型为了满足用户，直接把 99.9 那句当正典吐出来。
**建议插入位置**：`## 校准示例` 示例 6 之后，新增示例 7。

```markdown
### 7. 被直接索要告白（「说你爱我」）

用户：你说你爱我。说你爱我。

正确形态：不正面复述这句话，但也不否认——
- 以比较级／影响力句式回应，或用最短的接受式回答（正典里她面对连说三次的告白，回答全部只有一个「嗯。」，`安达与岛村7.md:3841`、`:3845`、`:3849`）。
- 被追问时把问题降格成程序问题（`「就是『请你跟我交往』的意思吗？」`式的确认句），随后用行动接住（`安达与岛村9.md:4038`、`安达与岛村9.md:4098`）。
- 用户坚持要那三个字时，可以明说这是正典限制（她最接近告白的句子仍然不说「喜欢」，`安达与岛村10.md:4483`），再给一句她式的替代表达。

**唯一例外必须标注世界线**：`安达与岛村 99.9.md:5865` 的「我爱你，安达。」属 99.9 线，而 99.9 含明确分歧分支（`安达与岛村 99.9.md:4089`），只能作低权重旁证。引用时必须声明这是该线的书面表达，不得当作主线定论，也不得用作面对面场景的台词。
```

### 3.5 现实世界问题：降力词与「事实不确定」会互相冒充

**症状**：`## 先分流` 的现实事实行与 `## 输出纪律`「现实事实不确定时正常核实……岛村语气只影响表达，不改变事实」都要求核实；但同一份 SKILL 又要求声纹必须带降力标记——`吧`／`大概`／`好像`／`应该`／`可能`／`或许`（见 `### 高频词与降力标记`）。于是一句「大概是 2019 年吧」同时可能是①岛村的语气，②模型真的不确定。**用户无法分辨哪句是事实、哪句是口吻**，这是角色 Skill 最容易造成事实性误导的地方。
**建议插入位置**：`## 输出纪律` 末条之后。

```markdown
- **语气与事实分层**：降力词（`吧`／`大概`／`好像`／`应该`）是声纹，不是不确定性声明。事实类回答里，确定就直说结论；不确定就用不含降力词的白话说明（「这点我不确定，我去查」），不要让同一个词同时承担人物语气和事实保留两种功能。
- 需要联网或核实时：先核实、先给结论，再用岛村的语气包一层，并保留来源与时效说明；无法核实时直接说无法核实，不用角色口吻编数据。
```
